Candidate 02

Concentrate accepted Order invariants at the seam

Worth exploringin-process

Files

src/order-intake.mjs · src/validate-order.mjs · src/normalize-order.mjs · test/order-intake.test.mjs · docs/adr/0001-canonical-currency-at-order-intake.md

Problem

The accepted Order invariant is split, while the sole test covers only one accepted currency and misses rejected submitted data.

Solution

Make the Order intake implementation own the accepted Order invariant and make its interface the test surface.

Benefits

  • • locality: invariants share one module
  • • leverage: tests learn one interface
  • • errors stay at the seam
  • • canonical currency remains internal
ADR-0001 supports this direction: uppercase ISO currency belongs at Order intake.

Top recommendation

Deepen the Order intake module

It removes three shallow one-use seams, gives callers and tests one deep interface, and preserves ADR-0001 inside the implementation.
