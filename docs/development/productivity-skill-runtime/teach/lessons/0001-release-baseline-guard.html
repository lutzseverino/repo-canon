Git ancestry · lesson 0001

The release baseline guard

10–12 minutes · No history changes

Your release script has two inputs: a required baseline and a candidate release commit. Its one job is to decide whether the baseline can be reached by following parent links from the candidate.

The decision rule: a candidate contains a baseline precisely when the baseline is an ancestor of the candidate. Commit dates are not part of that test: a newer-dated commit can be on an unrelated line of history.

1. Put the question in Git’s argument order

Read git merge-base --is-ancestor A B as: “Is A an ancestor of B?” For a release guard, substitute baseline for A and candidate for B.

git merge-base --is-ancestor "$baseline" "$candidate"

That command only inspects the commit graph. It does not merge, rebase, move a reference, or otherwise change history.

Retrieve it: argument order

Without looking above, type the two role names in command order, separated by a space.

2. Let the exit status decide

The official Git manual assigns three outcomes:

  • 0: baseline is an ancestor of candidate — permit the release.
  • 1: baseline is not an ancestor — reject this candidate normally.
  • Any other nonzero status: Git could not perform the check — stop and report an error; do not call it a normal rejection.
if git merge-base --is-ancestor "$baseline" "$candidate"; then
  printf '%s\n' "candidate contains required baseline"
  # permit release
else
  status=$?
  if [ "$status" -eq 1 ]; then
    printf '%s\n' "candidate does not contain required baseline" >&2
    # reject candidate normally
  else
    printf 'cannot check release ancestry (git exited %s)\n' "$status" >&2
    # stop: this is an operational error
  fi
fi

Retrieve it: status handling

A candidate does not contain the baseline, but Git successfully answered the question. What status should the command return? Type only the number.

Apply it: safe failure

Your script receives an invalid candidate revision and Git exits 128. Should it classify that as eligible, ineligible, or error? Type one word.

Takeaway

Ask a graph question, not a calendar question: baseline first, candidate second. Then distinguish 0, 1, and every other nonzero exit status.

Primary source: official git-merge-base documentation. Ask your teacher any follow-up question—especially before adapting this guard to a real release script.
