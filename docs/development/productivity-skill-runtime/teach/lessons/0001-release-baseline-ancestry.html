Lesson 0001 · 10 minutes

Baseline ancestry for releases

Make one safe decision: does this candidate release commit already contain the required baseline?

Your release question

Your script has a required baseline commit and a proposed candidate commit. The candidate is acceptable only if the baseline is an ancestor of it: starting at the candidate, Git can reach the baseline by following parent links.

baseline (B) ──► R ──► candidate (C)

Start at C; follow parent links left: C → R → B.

Important: the arrows draw history left-to-right for readability. The test is reachability in the graph, not which commit has the earlier timestamp.

The command reads like the question

git merge-base --is-ancestor <first> <second>

The official documentation defines this as: is the first commit an ancestor of the second? For your release question, put the thing that must be included first:

git merge-base --is-ancestor "$baseline" "$candidate"

Retrieval 1 — choose the order

A release requires B, and its candidate is C. Which pair follows --is-ancestor?

Read the status as a three-way decision

In this mode, Git prints no answer; the exit status is the answer. The official contract is:

  • 0: true — the baseline is an ancestor of the candidate.
  • 1: false — the baseline is not an ancestor of the candidate.
  • anything else: an error — do not silently convert it into false.

This distinction protects a release script from accepting an invalid revision name, repository problem, or other command failure as an ordinary “baseline missing” result.

Retrieval 2 — classify the result

The command exits 1. What should the release decision be?

Use it safely in a script

git merge-base --is-ancestor "$baseline" "$candidate"
status=$?
case "$status" in
  0) printf '%s\n' 'candidate contains baseline' ;;
  1) printf '%s\n' 'candidate lacks baseline'; exit 1 ;;
  *) printf '%s\n' 'could not check ancestry' >&2; exit "$status" ;;
esac

The order is deliberate: read it as “is $baseline an ancestor of $candidate?” No dates or history-changing commands are involved.
