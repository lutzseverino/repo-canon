# Repo Canon project guidance

Repo Canon authors a standards source for the separate Repository Standards
product. Use the confirmed preferences in `authoring-notes.md` and review the
draft contents in `design-review.md` before changing the intended standards.

The repository is a work in progress. Root contribution and agent configuration
files are working copies of the selected conventions; `drafts/` retains the
interview's design material. Read current files before promoting or revising a
draft. The source manifest, automation, pinned skill directories, and behavioral
verification are not implemented yet.

The next planning step is a GitHub specification synthesized from the recorded
decisions, followed by implementation tickets. Keep source authoring separate
from the product scope work described in
`docs/development/scope-capability-specification.md`. The product interface is
still a proposal; do not invent unsupported manifest fields or narrow the
accepted policy to bypass that dependency.

Use `docs/development/README.md` for the current validation requirements. Source
licensing is an outstanding owner choice; the absence of a LICENSE file is not
a license selection or a claim of release readiness.
